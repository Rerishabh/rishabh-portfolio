# Design Direction

## Experience intent

Systems Field Journal should feel like a thoughtful record of systems work,
research, experiments, and learning. The design should prioritize clarity,
evidence, and contribution over decorative claims.

## Public project presentation

Project surfaces should emphasize:

- project name
- category
- concise accurate description
- technologies
- personal contributions
- verified “Live Demo” and “Source Code” actions when available

Unavailable information should be omitted. TODOs, placeholder values, and
internal notes must never be visible.

## Metadata constraints

Do not use completion, unfinished-work, incomplete-work, or submission labels in
the public visual language. Do not add status badges, metadata chips, or
descriptions that communicate internal tracking state.

Website inventory notes are not public labels. A project with a verified URL may
show a link action; a project without one simply has no live-demo action.

## Content safety

HackerRank Orchestrate September may be represented as a high-level project
entry only. Do not show private datasets, challenge files, private URLs, or
repository contents.

## Creative feature

**OPEN.** The visual concept for the primary creative feature is not selected.
The design process must not default to a pathfinding visualizer.

## Responsive principles

- Keep project content readable at narrow widths.
- Make action links obvious without relying on status color.
- Preserve hierarchy through typography, spacing, and grouping.
- Avoid decorative elements that imply unverified results or achievements.
