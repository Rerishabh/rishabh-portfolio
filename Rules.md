# Rules

## Public content rules

1. Show only verified project information.
2. Project cards may show name, category, description, technologies,
   contributions, and verified action links.
3. Render a “Live Demo” action only when a verified live URL exists.
4. Render a “Source Code” action only when a verified public repository URL
   exists.
5. Omit unavailable fields instead of showing TODO text, empty placeholder
   labels, or invented content.
6. Do not add status-oriented metadata badges.
7. Do not display completion tracking or hackathon submission tracking.
8. Do not put internal tracking details in public descriptions or the public
   README.

## Inventory rules

Notes such as “with website” and “without website” are internal classification
tags. Visitors see action links only when the corresponding URL is verified.

## Accuracy rules

- Keep KinoCheck Eval generic and non-sensitive until an accurate description
  is supplied.
- Keep unresolved descriptions, technologies, contributions, and URLs as
  internal TODOs.
- Never infer technologies, results, achievements, or contributions.
- Never expose private datasets, challenge files, or private repository links.

## Exclusion rules

- Do not include StadiumGenie AI in the public project list.
- Do not include the incomplete DBMS project in the main portfolio.

## Implementation rules

- Do not create UI components until the documentation checkpoint is approved.
- Keep the primary creative feature **OPEN**.
- Do not implement a pathfinding visualizer as the primary creative feature
  without a later explicit decision.
