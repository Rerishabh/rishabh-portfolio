# Product Requirements Document

## Product

**Systems Field Journal** is a personal portfolio for the AWS Student Builder
Challenge. It should communicate how the author thinks, builds, researches, and
contributes without inventing evidence or exposing private material.

## Goals

- Present a clear, accurate portfolio of 12 approved projects.
- Make each project understandable through its verified description,
  technologies, and contributions.
- Provide verified repository and live-demo actions when available.
- Keep incomplete or unverified information out of visitor-facing content.
- Preserve a systems-oriented editorial identity rather than presenting a
  generic project gallery.

## Visitor-facing project content

Each public project may contain only:

- name
- category
- accurate description
- technologies
- contributions
- verified repository URL
- verified live URL

Missing fields remain internal TODOs. The public experience omits missing fields
instead of rendering placeholders.

## Explicit non-goals

- Do not publish internal project tracking metadata.
- Do not publish hackathon submission information.
- Do not expose private datasets, challenge files, or private repository links.
- Do not claim features, results, achievements, technologies, or contributions
  that have not been verified.
- Do not make a pathfinding visualizer the primary creative feature.
